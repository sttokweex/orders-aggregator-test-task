# Решение

## Что изменено

- Добавлена миграция `002_amount_paid.sql`: сумма фактической оплаты хранится в целых копейках в `amount_paid_kop`. Старые записи получают `amount_paid_kop = amount_kop`.
- При синхронизации и вебхуках читается `amountPaid`. Если поле отсутствует у старого заказа, оплаченная сумма принимается равной `amount`. `discountPercent` проверяется на диапазон 0–100, но денежным источником истины служит `amountPaid`.
- `daily-totals` возвращает `total`, `gross`, `discount`, `net` для каждого дня, включая дни без оплат. `total = gross`, `discount = gross - net`. Суммы агрегируются в копейках; перевод в рубли делается только для ответа.
- Локальная дата каждого заказа теперь определяется по IANA-таймзоне клиента на момент создания этого заказа. Поправлена потеря копейки из-за погрешности двоичного представления чисел при переводе рублей в копейки.
- Добавлены тесты для скидок, обновления заказа вебхуком, точности копеек и перехода на летнее время. Сигнатура `createContainer(db, api)` и интерфейс `OrdersApi` сохранены.

## Причина расхождения

Клиент `c_7` находится в `Europe/Berlin`. 29 марта 2026 года Берлин переходит с UTC+1 на UTC+2. Раньше сервис один раз вычислял смещение **на момент запроса** и применял его ко всем заказам периода. Заказы около полуночи после перехода попадали в предыдущий день. Например, заказ `o_02357`, созданный `2026-03-29T22:40:08Z`, относится к 30 марта, 00:40 по Берлину; при смещении UTC+1 он ошибочно относился к 29 марта.

Причину нашёл при разборе `src/services/totals.ts`: там перед циклом вызывался `tzOffsetMinutes(timezone, new Date())`. Сравнил даты заказов вокруг 29 марта с `created_at AT TIME ZONE 'Europe/Berlin'` в PostgreSQL и добавил тест на обе стороны перехода.

## Проверка

1. `npm run typecheck` — успешно.
2. `npm test` — 32 теста проходят (PostgreSQL из `docker compose`).
3. На чистой основной БД: `docker compose up -d`, `npm run migrate`, запуск сервиса, `POST /sync` до завершения, затем `docker compose run --rm orders-api webhooks --target http://host.docker.internal:3000/webhooks/order` до завершения.
4. Синхронизация: 52 страницы, 5030 получено, 4853 применено, 177 невалидных пропущено. Вебхуки: 92 отправлено, все получили HTTP 200. После этого запрошен `daily-totals` для `c_7` за 27–31 марта; ответ сохранён в корневой `result.json`.
5. Суммы `gross` и `net` для всех пяти дней независимо сверены с SQL-группировкой по `created_at AT TIME ZONE 'Europe/Berlin'`; совпадают до копейки.

## Допущения и наблюдения

- `amountPaid` — авторитетное значение фактической оплаты. Процент скидки не пересчитывается в деньги: это могло бы дать другое округление.
- Для старых заказов без `amountPaid` скидка равна нулю. При долях копейки сохраняется прежнее правило сервиса: отбросить долю копейки.
- Внешний API завершает список пустой страницей с повторяющимся курсором; существующая логика синхронизации это учитывает. На данном наборе есть 177 записей, которые существующий валидатор пропускает как невалидные.
- На машине порт 5432 занят другим PostgreSQL, поэтому порт контейнера назначен 55432; пример `.env` и тестовая конфигурация обновлены соответственно.
